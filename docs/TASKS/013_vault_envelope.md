# 013 · مظروف الخزنة

**المرحلة:** M4 · **الحالة:** تمّت (commit واحد مع 014 و015)

## القاعدة الرابعة (المالك)
```
passphrase → Argon2id → مفتاح يفكّ  master key عشوائي
                                    ↓
                       الـmaster key يشفّر جسم الخزنة
```
فتغيير كلمة المرور يُعيد لفّ **٣٢ بايتاً**، لا الخزنة كلّها.

## ما دخل
- `vault/crypto.rs`: Argon2id (٦٤ ميغابايت · t=3 · p=1 لخزنة جديدة) + ChaCha20-Poly1305، و`Zeroizing` يمسح المفاتيح عند الخروج.
- **لكلّ خزنة salt عشوائي خاصّ**، ومعلمات KDF محفوظة **داخل الملفّ** مع `FORMAT_VERSION`. فالخزنة تُفتح بالأرقام المكتوبة فيها، لا بأرقام هذا البناء — ويمكن رفع الكلفة غداً للخزائن الجديدة دون كسر القديمة.
- ثلاث اعتماديات مبرَّرة (بصياغتك لـG1: غير شبكيّة، مثبّتة، مبرَّرة): `argon2` · `chacha20poly1305` · `zeroize`.
- التنسيق مكتوب بيدي، مُطوَّل الطول ومُرقَّم: `ZVLT` + إصدار + مجموعة التشفير + الأرقام + salt + مفتاح ملفوف + جسم. أضفتُ dependency للتسلسل؟ لا — كتابة أربعة أرقام لا تستحقّ توسيع ما يجب تدقيقه.
- كتابةٌ إلى ملفّ جانبي ثمّ `rename`، فلا يتركنا انهيارٌ بنصف خزنة.

## البرهان الذي يجعل المظروف حقيقةً لا ادّعاءً
`changing_the_passphrase_does_not_touch_the_body`: بايتات الجسم **متطابقة** بعد تغيير كلمة المرور، والمفتاح الملفوف مختلف، والكلمة القديمة ميتة. ولو أُعيد تشفير الجسم لفشل الاختبار — وهذا معنى «المظروف».
وكذلك: كلمة مرور خاطئة ⇒ `VaultLocked` فقط ولا شيء يُستفاد؛ وملفّ مقطوع أو من إصدار أحدث ⇒ يُرفض بسببه.

## قرار صغير
تغيير كلمة المرور **يُبقي كلفة الخزنة كما هي** (salt جديد فقط). رفع الكلفة عملٌ مقصودٌ منفصل، لا أثرٌ جانبيّ لتغيير كلمة.
